## 2. Responsibility and identity contract
Market Data Processor: ordered per-source transport/JSON/L2 normalization and prepared chain provenance. Engine: accepted source book, actual current sequence/checksum/witness/identity, selected active and standby pair, epoch/highwater, final publication/Permit. UCM: ordered connection/transport/quality facts, qualification, expiry, challenger/election advice, applied active. UCM cannot mint Permit or mutate Engine market books. Market Owner/Decision: current selected cross-venue state for each base and evaluate existing routes. Consolidate repeated mutable state only after exact parity; use immutable selected input through existing boundaries. Bridge validates authenticity and actual-time eligibility, not an election engine.
Distinguish three independent identities:
- Immutable accepted market event: source ID including exchange, segment, instrument, channel, physical connection, session and generation; ordered receive identity/sequence, original payload hash, normalized book, event/receive clocks. Not a permission to trade.
- Stream validity/authority lineage: destructive generation/close/reset/chain invalidation, exact validator-issued live witness. Existing SnapshotWitness per-full-snapshot behavior remains unchanged until dedicated contract approval; old witness cannot be resurrected. Need explicit distinction between an immutable observation and current permission; do not silently admit old events.
- Actual selected authority: current selected source, distinct independent standby, selection epoch, their live evidence and both age bounds, current highwater. Permit at point of use; current UCM applied state relevant to scope. Selection changes only on accepted applied ACK. A new sequence is not by itself an election or new selection epoch.
Revision protocol: retain existing ordered UCM FIFO + producer/applied revision. Scope authority invalidation counter advances on destructive transition BEFORE submission; a separate market revision increments for accepted source facts and eligibility changes, and choice basis includes exact current eligible IDs + owner quality/challenger state. Publication carries applied watermark and scope versions. Pending facts are not assumed applied. If version compatibility cannot be proven, affected scope is denied; systemic FIFO full/gap/closed/poison fails closed. Coalesced Notify is wake only, not an event; revoke->recover must never disappear. Avoid scanning universe on every wake: bounded one record per registered scope and ready membership, not a queue of frames. Keep exact existing event order and fairness.

## 3. Proposed explicit state machine
One scope record in existing Engine keyed by venue/base (mapping to UCM full scope must be injective in configured channels). Source facts remain under existing owner; continuation is scope-local, not duplicate book storage. States:
Unqualified (no admissible pair), Active (applied selected source and current eligible independent standby), Switching (one real commit pending for scope; no new authorization without proof), Revoked (scope unsafe/unknown), Faulted (ordered protocol failure; systemic if relevant).
Events and transition:
1. Connected/Subscribed: register exact source generation, warm only, UCM ordered event. No Permit. Mark only affected scope for progression.
2. ValidBook: preserve original decoder/sequence/checksum/accepted-predecessor/generation/clock rules; update accepted source facts and deliver Observe. Current full snapshot revoke/mint stays intact. When matching applied owner facts available, evaluate final actual-time gate for that scope; if same active, no fresh election roundtrip solely for book refresh. Retain previous Permit only when its exact witness and independent standby remain valid, no pending destructive event, current identity and both ages proven. Otherwise revoke, then refresh Permit on new proof. If source selection not established or actual choice changed, go Switching. Preserve ordered accepted market events; no latest-only shortcut without approved semantics.
3. InvalidBook: branch by original category. Stale rejected/keepalive cannot extend market freshness. Preserve old still-valid proof only when existing semantics permit and no destructive transition. Sequence/checksum/reorder/book reset/generation conflict revoke per original rules; quarantine/resync exact scope. Send original mandatory UCM facts; no lost events.
4. Owner advice: apply only current compatible scope basis, recheck candidate eligibility, independent standby, live witness, highwater and both clocks. Advice for same active is not Commit; publish if eligible. Choice change starts one scoped plan/Commit (original policy reasons/tie/hysteresis unchanged). Advice never grants authority. A quality update affects challenge timing even if active stays same.
5. AppliedSwitch ACK: verify exact scope/source/prior/epoch/generation/basis, current eligibility and actual applied UCM active. If superseded, reconcile owner active and current selection while scope closed. Valid transition emits Reset then permitted book in order; no duplicate epoch/reset. No unrelated scope waits for ACK.
6. Deadline: separate receive deadline inclusive800ms -> expired at +800000001ns; wall deadline inclusive800ms -> +801ms. Expiry of selected or any required standby revokes before use and schedules affected scope only. UCM qualification/5s dwell deadlines separate; quality must re-evaluate challenger only on affected facts or due time. System watchdog at existing50ms; retain existing full safety schedule until true differential proof of no-later revoke. Wall/mono discontinuity explicitly invalidates/re-evaluates affected/global clock domain. Do not turn monotonic estimate into proof of wall freshness.
7. Closed/Reconnect/Reset: revoke exact affected authority/witness immediately before any optional work, mark relevant generation retired, reject late old frame/ACK. No global select to handle one socket close. Bound live source facts to configured active generations; retirement keeps sufficient ordered tombstone to reject late events until producer/consumer barrier proves unreachable. Never blindly clear dedup protection.
8. History/census: ordered required safety/recovery facts remain mandatory, optional diagnostic receipt cannot occupy global selection progress. No dropped authoritative event. Bounded diagnostic counters and samples observe already applied facts. If a required receipt is pending, only dependent scope may be held, systemic failure still fails closed.

Evaluate existing Decision per affected base, Risk/Safety rechecks on actual order admission. No DB in negative/ordinary quote work except explicitly preserved old obligation/recovery boundary.
