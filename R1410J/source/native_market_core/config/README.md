# SPOT-ARB R32D6C8A — конфигурация Native Rust

Это **изолированная review-копия** старого `/home/tmpadmin/spotbot/config.yaml`.
Исходный Python-конфиг не менялся. Здесь сохранены 26 исходных разделов и 156
конечных значений/списков с теми же YAML-ключами.

- `native_trading.yaml`: привычные старые параметры, плюс служебный
  `native_runtime` с тремя явными запретами на real/trading/cutover.
- `native_field_schema.json`: точные имена и типы всех полей; нативный
  парсер Rust отклоняет отсутствующие, новые или изменённые по типу параметры.
- `native_field_status.json`: по каждому полю указано, перенесено ли оно
  только как данные или уже участвует в read-only проверке Rust.
- `telegram.proxy_url`: значение намеренно очищено до пустой строки,
  поскольку старый proxy URL может содержать секреты. Сам ключ сохранён.

## Как проверить без торговых действий

Из каталога `native_market_core`:

```sh
cargo run --bin r32d6c8_config_inspect -- config/native_trading.yaml
```

Этот инструмент **только читает YAML**, проверяет типы, показывает безопасные
лимиты и SHA-256 конфигурации. Он не читает секреты, не вызывает биржи,
не открывает позиции, не изменяет файлы.

## Важная граница статуса

`native_trading_config.rs` — нативный read-only загрузчик и **предварительный**
расчёт рисков по номиналу сделки, котировке и комиссиям. Это пока **НЕ**
подключение всех 156 параметров ко всем узлам Rust и **НЕ** разрешение
производственных торговых действий. Подробная маркировка по каждому параметру
есть в `native_field_status.json`. Даже при успешной проверке сумма ордера
не превращается в разрешение на его отправку.

В старой конфигурации `risk.max_open_positions: 10` относится к общим
лимитам, а `real_trial.max_open_positions: 1` — к real trial.
`real_trial.max_trades_per_day: 0` продолжает полностью запрещать реальные
входы. `operator_approved` и `autonomous_real_enabled` сохранены как
наследованные данные, но **не** являются разрешением для Rust. R32D6C1
запрещает сетевые mutation запросы, R32D6C4 запрещает Native Hedged.

Следующий обязательный этап — R32D6C8B: подключить проверенную конфигурацию
как единственный источник параметров к DecisionCore, native state creation,
risk counters/cooldown, order permission, telemetries/Telegram с безопасным
сохранением поколения, проверкой ранее заданного cap и тестами на отказ.
Только после этого можно говорить о завершённом переносе.

## R32D6C8B1 — частичное подключение конфигурации к NativeStateStore (09.10.2026)

Добавлен `begin_native_entry_with_config(...)`: **до** записи Prepared intent
загружается именно YAML из переданного review-пути, валидируется расчёт
спотовой и фьючерсной ноги с резервом комиссий, цена и объём, safety generation.
Под OS writer lock перед fsync YAML проверяется повторно, а SHA-256 YAML,
изначальные цены и рассчитанный предельный notional сохраняются в поле
`NativeEntryAuthority.policy_binding`. Старые state-файлы без поля открываются
без смены сериализованного формата (serde default+skip when None).

На позициях с `policy_binding` обычная `authorize_entry_order(...)` и
`prepare_futures_entry_hedge(...)` **отказывают**: необходимы отдельные
`authorize_entry_order_with_config(...)` и
`prepare_futures_entry_hedge_with_config(...)`, где снова сверяется исходный
SHA-256 и весь расчёт при новой загрузке файла. Проверка суммы подтверждённых
подписанными GET спотовых сделок и комиссий встроена в
`record_native_spot_first_leg_evidence(...)` и в state validator — превышение
исходного лимита не записывается как сертифицированный результат.

**Ограничения:** у старого `begin_native_entry(...)` для исторических тестов
сохраняется путь без policy binding; он пока не закрыт для всех будущих
production caller'ов. Единого durable суточного счётчика сделок, реального
учёта занятых позиций, механизма эксклюзивной блокировки при конкурентной
смене YAML, полной проверки lot-step/min-notional/незахеджированных объёмов,
полной привязки `config_sha256` к AI/Decision/Telegram и сквозного executable
release gate пока нет. Перед подлинным production cutover всё перечисленное
нужно завершить. В обычной review-сборке реальные private network mutations
по-прежнему физически запрещены R32D6C1, Native Hedged — R32D6C4.

## R32D6C8B2A — native review paper accounting, YEKT calendar

NativeDailyRiskLedger is optional, backward-compatible serde-default field
inside NativeAuthoritativeState. No legacy snapshot is rewritten.
reserve_paper_daily_slot() validates SHA256 of YAML, the previous journal,
the unique paper attempt ID, owner state generation CAS, day based on
Asia/Yekaterinburg UTC+05:00, actual enabled PAPER mode and occupancy. It
persists a single atomic native state after file fsync and parent fsync.
release_paper_daily_slot() marks a PAPER slot closed with an independently
supplied synthetic close ID; it NEVER refunds the spent attempt on that day.
Both are idempotent for same exact IDs across restarts and day rollover.
Concurrent attempts under one expected_generation allow only one writer.

Legacy config continues to have general.paper_entries_enabled=false,
real_trial.max_trades_per_day=0, real_trial.max_open_positions=1 and
real_trial.entry_cooldown_sec=10800. Both paper and real entry are DENIED
by default. Separate purely local mocked YAML temporarily enables paper
reservations to exercise source limits. No production YAML was changed.
In Python, 300 general max trades/day and 3000 PAPER attempts/day are
mode-selected, NOT both applied to paper. A stronger paper limit below 300
is valid and safe. This parity is now reflected in the YAML parser.

HARD LIMITS/unfinished:
This is an isolated PAPER accounting register, not proof of actual
exchange-trade opens or closes. Recording a paper close ID is not an
independent exchange-backed verification. Real has a hard zero-entry
gate, but real cooldown and real verified close timestamps lack native
exchange truth. Paper reservation is not yet mandatory for historical
begin_native_entry() callers, and there is no fully integrated paper
DecisionCore/position manager wiring yet. Ledger records and IDs are
bounded to 30,000: fail closed rather than silently discard replay
history. Mock now_ms is caller-provided; authoritative clock and
monotonic reboot-safe time require an additional gate. Real commission/
loss limits, size-map lot constraints, Telegram and remaining YAML
consumers are NOT wired. Do not call this full R32D6C8B completion.
No production cutover. R32D6C1 and R32D6C4 hard stops unchanged.
