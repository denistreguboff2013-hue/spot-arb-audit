## Why the existing workers cannot be reused as HOT authority
`native_market_core/src/r1352_diagnostic_worker.rs` uses `sync_channel` with `try_publish` that returns false and DROPS messages on Full/Disconnected (and the shard publisher also drops). Correct for diagnostics, **unsafe for HOT lifecycle/quality/authority**. Existing `MarketDataProcessor` Forwarder sees speculative preadmission books and per-session state, not final cross-source accepted state; granting HOT there would violate generation, chain-predecessor, validation and dual-HOT authority. Tokio 1.x bounded `mpsc::send` cancellation can lose an unsent message, `reserve` reserves capacity and is FIFO; a started `spawn_blocking` task is not cancellable (Context7 Tokio documentation checked 2026-11-24, sources https://github.com/tokio-rs/tokio/blob/master/tokio/src/sync/mpsc/bounded.rs and https://github.com/tokio-rs/tokio/blob/master/tokio/src/task/blocking.rs). Existing Cargo.lock pins Tokio **1.36.0**; any new runtime implementation must validate against that actual version.
